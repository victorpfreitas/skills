# Formato Série/Antologia — Referência

Use quando o projeto é uma série de episódios curtos (30s-90s) com um formato
repetível — como MIB Divisão Brasil. O objetivo aqui é separar o que é **fórmula
fixa da série** (não muda a cada episódio) do que é **variável de cada episódio**
(muda toda vez) — sem essa separação, cada episódio novo vira um processo do zero.

---

## O que trava na primeira vez, e nunca mais se discute

Depois que o primeiro episódio (piloto) estiver fechado bloco a bloco, extraia e
registre num resumo curto:

```
FÓRMULA DE BLOCOS: [a sequência de blocos que a série usa -- ex: abertura in media
res -> sinal sonoro -> primeiro contato -> conflito de comunicação -> gatilho de
escalada -> resolução externa -> cena de testemunhas -> encerramento-assinatura]

ASSINATURA DE ENCERRAMENTO: [o gesto/imagem que fecha todo episódio -- ex: o flash
do apagador de memória]

REGRAS DE MUNDO: [ver worldbuilding.md -- essas não mudam entre episódios]

FICHA DE PERSONAGEM FIXO: [ver personagem.md -- o protagonista que atravessa a
série]

ASSINATURA DE TOM: [ver dialogo-tom.md -- as três respostas travadas]
```

Depois disso, ao começar um novo episódio, **não repita as perguntas de fundação**
(personagem, tom, mundo) — cite o resumo travado no início da resposta, e vá direto
pras perguntas específicas daquele episódio: qual entidade/caso, qual cenário, qual
prop de callback específico daquele episódio.

---

## O que varia a cada episódio

```
- Entidade/caso central (banco de casos -- pode ser mantido como lista viva,
  adicionando novos conforme surgem ideias em conversa)
- Cenário específico
- Prop de callback específico daquele episódio (o "gatilho" pode reaproveitar a
  mesma regra de mundo mas usar um objeto diferente a cada vez, ou o mesmo objeto
  -- pergunte a Victor qual ele prefere pra série)
- Grau de contato / intensidade do encontro (se o mundo tiver esse sistema)
- Se o Victor entende ou fica alheio à ironia da situação (variação intencional já
  combinada para esta série -- ver dialogo-tom.md)
```

---

## Banco de casos — como manter vivo

Sempre que uma ideia de "próximo episódio" surgir em conversa (mesmo de passagem),
registre numa lista simples, sem desenvolver ainda:

```
BANCO DE CASOS -- [nome do projeto]
- [nome do caso] -- [1 linha de gancho/o que torna esse caso diferente dos outros]
```

Isso evita perder ideias soltas e dá a Victor uma lista pra escolher "qual episódio
eu quero desenvolver hoje" sem precisar reinventar a lista toda vez.

---

## Quando propor variação na fórmula

Fórmula fixa é boa pra reconhecimento, mas pode cansar depois de muitos episódios.
Se Victor já tiver 5+ episódios da mesma fórmula, vale perguntar (não decidir
sozinho) se ele quer manter 100% fixo ou introduzir uma variação pontual (ex: um
episódio sem a cena de testemunhas, ou um episódio onde a fórmula quebra de
propósito como efeito especial de "episódio diferente"). Trate isso como decisão
estratégica de Victor, não ajuste automático seu.
