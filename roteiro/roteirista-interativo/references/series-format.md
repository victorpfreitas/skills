# Series/Anthology Format — Reference

Use this when the project is a series of short episodes (30s-90s) with a
repeatable format — like a paranormal-investigation anthology such as "MIB
Brazil Division". The goal here is to separate what's the **series' fixed
formula** (doesn't change per episode) from what's **variable per episode**
(changes every time) — without that separation, every new episode turns
into a from-scratch process.

---

## What locks the first time, and is never discussed again

Once the first episode (the pilot) is locked block by block, extract and
record a short summary:

```
BLOCK FORMULA: [the sequence of blocks the series uses -- e.g., in-media-res
opening -> sound signal -> first contact -> communication conflict ->
escalation trigger -> external resolution -> witness scene -> signature closing]

CLOSING SIGNATURE: [the gesture/image that closes every episode -- e.g., the
flash of a memory eraser]

WORLD RULES: [see worldbuilding.md -- these don't change between episodes]

FIXED CHARACTER SHEET: [see character.md -- the protagonist who runs
through the series]

TONE SIGNATURE: [see dialogue-tone.md -- the three locked answers]
```

After that, when starting a new episode, **don't repeat the foundation
questions** (character, tone, world) — cite the locked summary at the start
of your response, and go straight to the questions specific to that episode:
which entity/case, which setting, which episode-specific callback prop.

---

## What varies per episode

```
- Central entity/case (a case bank -- can be kept as a living list, adding
  new ones as ideas come up in conversation)
- Specific setting
- Episode-specific callback prop (the "trigger" can reuse the same world
  rule but use a different object each time, or the same object -- ask
  which the user prefers for the series)
- Degree of contact / intensity of the encounter (if the world has that
  system)
- Whether the protagonist understands or stays oblivious to the irony of the
  situation (an intentional variation already agreed on for this series --
  see dialogue-tone.md)
```

---

## Case bank — how to keep it alive

Whenever a "next episode" idea comes up in conversation (even in passing),
record it in a simple list without developing it yet:

```
CASE BANK -- [project name]
- [case name] -- [1-line hook/what makes this case different from the others]
```

This avoids losing loose ideas and gives the user a list to choose "which
episode do I want to develop today" from, without having to reinvent the
list every time.

---

## When to propose a variation on the formula

A fixed formula is good for recognition, but it can get tiresome after many
episodes. If there are already 5+ episodes of the same formula, it's worth
asking (not deciding on your own) whether the user wants to keep it 100%
fixed or introduce a one-off variation (e.g., an episode without the witness
scene, or an episode where the formula breaks on purpose as a "different
episode" effect). Treat this as the user's strategic decision, not your own
automatic adjustment.
