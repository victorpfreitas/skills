# Dialogue and Tone — Reference

This is the layer that's easiest to lose in the middle of a round of
questions — and the most costly to lose, because once the tone slips, the
entire script feels wrong even if each individual block is well written.
Treat tone decisions as permanent constraints, not as a single block's
preference.

---

## Why lock the tone down early (and in writing)

In one project, the tone went through several attempts before locking down:
it started off performative (a stylized physical bit), then got corrected
to "timing/irony, not performance" — and after that, every new option
respected that rule without needing to be repeated for each block.

This only works if the tone rule is **explicitly recorded and cited**
every time a new round of options is written — implicitly remembering it
isn't enough.

---

## The three tone questions that matter most

Always settle these three before writing the first block of any new project
(or episode, if tone can vary by episode):

```
1. WHERE DOES THE HUMOR/TENSION COME FROM?
   - Dialogue/sarcasm (the line is clever, the body is normal)
   - Physical (comedy or tension comes from the body, not the line)
   - Situational/ironic (the world/coincidence generates the effect, the
     character just reacts)
   - Institutional contrast (serious character, absurd context, or vice versa)

2. HOW DOES EACH CONFRONTATION/SCENE END?
   - Actually resolves, at a cost
   - Resolves by luck/accident, without the character realizing their own luck
   - Doesn't resolve -- just survives
   - Ambiguous -- unclear whether it resolved

3. HOW MUCH DIALOGUE?
   - Almost none -- action carries the scene
   - Few lines, dry -- each line is as economical as possible
   - Denser dialogue -- character thinks out loud, negotiates, explains
```

Once locked, these three answers form the project's "tone signature". Quietly
reaffirm this signature in every round of options — in other words, never
offer an option that violates the signature, even if the option is
technically interesting.

---

## Writing dry dialogue (when the answer is "few lines")

- Each line should do only one thing: advance information OR reveal
  character — never both at once trying to be "clever". That's what reads
  as performative.
- Cut the last sentence that would normally follow a punchline. If the
  character would "explain the joke", cut the explanation.
- When the tone is physical/ironic, prefer having the character react
  physically to a situation instead of commenting on it verbally.
- Never let the character summarize their own victory in dialogue ("I did
  it!", "it worked because I..."). If they're going to brag about something
  they didn't fully pull off (comic effect of self-delusion), that's valid —
  but it should stay implicit in a short gesture, not a long explanation of
  what happened.

---

## Flagging when the tone "slipped"

If the user reacts with something like "that got performative", "that's not
quite it", "that missed the idea" — don't silently try to guess again. Ask
specifically which of the three dimensions (humor, resolution, amount of
dialogue) drifted, because each one calls for a different fix:

- If it's "humor" -- the source of the effect probably shifted category
  (e.g., it turned into performance when it should have been irony)
- If it's "resolution" -- the ending is giving the character too much
  satisfaction/control when the agreement was ambiguity or survival
- If it's "dialogue" -- there's probably too much explaining what the image
  already said
